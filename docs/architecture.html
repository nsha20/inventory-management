Key Design Decisions

No database
All data lives in JSON files under server/data/, loaded once at server startup into memory. Changes are not persisted across restarts — intentional for a demo environment.
Centralized filter state
Four global filters (Time Period, Warehouse, Category, Status) are managed via a singleton useFilters composable. Every view reads from the same refs — no Pinia/Vuex needed.
Two-tier filtering
Backend handles warehouse/category/status/month filtering via query params. Views may then apply additional client-side filtering (e.g. search query) via computed properties.
Custom SVG charts
No charting library. All charts are hand-rolled with inline SVG inside Vue computed properties. CSS Grid handles dashboard layouts for full control over appearance.

Data Flow & Filter Pipeline

Filter Pipeline — Step by Step

1
User changes a filter in FilterBar.vue
Dropdown emits change → ref in useFilters.js is updated. All components sharing the composable react automatically.
2
View watcher fires
Each view watch()es the filter refs. On change, it calls getCurrentFilters() and invokes the API client.
3
api.js builds query string
Only non-'all' filters are appended as query params via URLSearchParams. Example: ?warehouse=London&status=delivered
4
FastAPI receives & filters
apply_filters() does exact match for warehouse, case-insensitive for category/status. filter_by_month() handles YYYY-MM and Q1-2025 formats.
5
Pydantic validates response
Response models ensure shape consistency before JSON is sent back. Validation errors surface as 422 responses.
6
Vue computed properties apply client-side pass
Views may apply a second filter layer (e.g. text search) via computed properties. Raw data sits in refs; derived views in computed.
